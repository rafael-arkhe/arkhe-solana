# O que o T0 NÃO afirma

Este documento é a declaração pública dos **limites (non-claims)** do registo T0 do Arkhe. É o artefacto mais importante do pacote: antes de declarar o que o método faz, declara o que este pacote *não* prova, para evitar equívocos sobre a natureza deste congelamento.

1. **O T0 não afirma que o Arkhe está implementado.**
   Este pacote regista uma especificação e um método, não código a correr em produção.

2. **O T0 não afirma prioridade sobre a ideia de "verificação de execução de IA".**
   A ideia geral não é protegível nem é o objeto deste T0. O T0 reivindica autoria apenas sobre a **formulação específica** e a arquitetura delineada (como o `IntentBinding`, a classificação τ, etc.).

3. **O T0 não afirma que os 28 INV-BB cobrem todas as classes de falha possíveis.**
   Eles representam a taxonomia conhecida nesta data, mas não fecham o universo de ataques.

4. **O T0 não afirma que os falsificadores foram executados.**
   Até que seja emitido um T1 com evidência de execução (mudando o estado de `PENDING` para `LEMMA`), os falsificadores são afirmações teóricas que a arquitetura *permite* testar.

5. **O T0 não impede que outros construam sistemas similares.**
   O T0 serve para tornar reivindicações comparáveis (com base nos detalhes metodológicos) e não para criar barreiras legais (não é uma patente).
